البورصة المصرية - منظومة جلب بيانات قابلة للتحقق، لا مجرد "أرقام من موقع"
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

> وثيقة المصادر والأفكار الأصلية (الخيارات الخمسة، الجدولة، أولويات المصادر)
> محفوظة كما هي في `EGX_DATA_STRATEGY.md` بجوار هذا الملف. هذه الوثيقة تصف
> **ما نُفِّذ فعلًا** مقابل تلك الخطة، والعقود الملزمة للطبقة.

THE PROBLEM THIS LAYER SOLVES
─────────────────────────────
الحالة قبل هذه الطبقة:
  - واجهات مجردة (egx_data_source.py) بلا أي تنفيذ حقيقى → لا fetcher واحد يعمل
  - بيانات قطاعات ومؤشرات مكتوبة يدويًا (hard-coded) بلا مصدر ولا تاريخ
  - مخزن SQLite بسيط (key/value) لا يعرف "من أين جاء الرقم" ولا "متى"
  - تحليل "أموال ذكية" بعتبات ثابتة (1.5 / 0.67 / 20 يوم) بلا معايرة ولا
    اختبار تاريخى → أرقام تبدو دقيقة وهى فى الحقيقة احتمالات بلا أساس

النتيجة العملية: أي رقم يخرج من المنظومة كان غير قابل للإثبات — لا نعرف
مصدره، ولا عمره، ولا هل اتفق عليه مصدر آخر أم لا.

WHAT THIS LAYER GUARANTEES (العقود الملزمة)
───────────────────────────────────────────
1. لا قيمة بلا إسناد (No value without provenance)
   كل قيمة تُعاد داخل Sourced[T] وتحتوى: المصدر، وقت الجلب، زمن الاستجابة،
   رقم المحاولة، حالة التطبيع (quality flags)، ومقارنات المصادر المتقاطعة.

2. "طازج" تُحسب بالتقويم لا بالساعة (Calendar-driven freshness)
   EGX تتداول الأحد→الخميس بتوقيت Africa/Cairo. الذى يجيب عن "هل هذه البيانات
   قديمة؟" هو EGXCalendar (مع DST المصرى الذى عاد 2023)، لا ثابت 86400 ثانية.

3. المصدر يعلن ما يستطيع تقديمه فقط (Declared capabilities)
   كل مصدر يعلن قدراته (Capability). الراوتر لا يسأل مصدرًا عن قدرة لم يعلنها،
   فمثلًا EGX الرسمى لا يعلن DAILY_OHLCV لأن صفحة التاريخ عنده ASP.NET postback.

4. الفشل مُسجَّل لا مُخفى (Failures are recorded)
   كل محاولة (ناجحة أو فاشلة) لها صف فى fetch_audit. AllSourcesFailed يحمل
   قائمة الأسباب كاملة. "لا بيانات" بلا سبب غير مقبولة.

5. لا تخمين فى تحليل الأرقام (No guessing in parsing)
   الأرقام العربية ١٢٣٤، فواصل الآلاف ٬ , .، النسب ٣.٠٢٪، السالب (2.04%)
   → كلها تُقرأ أو تُعاد None. لا يوجد "تقريب" صامت.

MODULE MAP (ما تفعله كل وحدة)
─────────────────────────────
calendar.py        تقويم التداول المصرى + جلسات اليوم + عقد الطزاجة.
                   الأحد→الخميس، 09:30 pre-open، 10:00 continuous،
                   14:20 closing auction، 14:30 post-close.
                   العطل الرسمية بيانات فى egx_holidays.json مع علم verified،
                   لأن الأعياد الهجرية تتحرك كل سنة ولا يجوز تخمينها.

provenance.py      Provenance و Sourced و QualityFlag.
                   كل رقم يحمل "فاتورته": المصدر، الوقت، زمن الاستجابة،
                   رقم المحاولة فى سلسلة البدائل.

transport.py       طبقة HTTP قابلة للحقن (Transport protocol):
                   - HttpxTransport: مهلات صريحة، إعادة محاولة بتراجع أسّى
                     + jitter، احترام Retry-After، وProxy.
                   - TokenBucket / HostRateLimiter: احترام الموقع الرسمى
                     (نصف طلب/ثانية لـ egx.com.eg افتراضيًا).
                   - FakeTransport: يجعل كل اختبار parser يمر بلا شبكة.

html_tables.py     قارئ جداول HTML بمكتبة standard library فقط (بلا bs4/lxml).
                   يحل مشكلة rowspan/colspan التى تُزيح الأعمدة وتجعل "الحجم"
                   يُقرأ كـ"سعر". يكتشف الترويسة بالوسم (<th>) أو بالمحتوى.

parsing.py         قراءة الأرقام العربية/الإنجليزية بلا تخمين:
                   ١٢٣٤ / 1,234,567 / 1٬234٬567 / (12.5) / 1.2M / ٣.٠٢٪

quality.py         فحوص الجودة على ثلاث طبقات:
                   - صلاحية بنيوية (hard): high ≥ low، high ≥ max(o,c)، …
                   - معقولية (plausibility): قفزة سعرية، انفجار حجم → OUTLIER
                   - اتفاق المصادر (triangulation): AGREEMENT/DIVERGENCE/CONFLICT

sources/           محوّلات المصادر:
  egx_official.py  كاشط موقع البورصة: مرشحات endpoints متعددة + تعلّم
                   الناجح منها (sticky)، قراءة جداول HTML أو JSON مضمّن،
                   ومطابقة أعمدة بمرادفات إنجليزية وعربية (الرمز/آخر سعر/…).
                   التقرير (ParseReport) يقول أي استراتيجية نجحت وأي حقول
                   غابت — وهذا الفارق بين "صفر صفوف لأن البورصة مغلقة" و
                   "صفر صفوف لأن الـselector اتكسر".
  yahoo.py         chart API (.CA لمصر): شموع يومية/daily وداخلية، مع إسقاط
                   الشموع الفارغة (null) لا تحويلها لأصفار، وتحقق من حدود
                   النوافذ (15m ≤ 60 يوم …) قبل إهدار الطلب.
  tradingview.py   محوّل يفوّض لطبقة tradingview_screener الموجودة أصلًا فى
                   المشروع (retry + cache) بدل بناء عميل ثانٍ بنفس العملية.
  base.py          Capability + SourceHealth + CircuitBreaker + SourceRegistry.

router.py          DataRouter: يسأل المصادر بالترتيب (الرسمى أولًا ثم
                   الأولوية ثم الصحى)، يشغّل بوابات الجودة، يقبل أول نتيجة
                   سليمة، ويكمل للتحقق المتقاطع عند الطلب، ويسجّل كل محاولة.

store.py           DataStore: SQLite بإصدارات مخطط (migrations)، WAL.

                   من كل مصدر!), quotes, index_levels, fetch_audit,
                   ingest_runs, quality_events.
                   + كشف الفجوات ohlcv_gaps() مقابل التقويم، لا مقابل "أمس".

ingest.py          EGXIngestor: دفعة تحديث = معاملة لها تقرير (ingest_runs).

                   آخر جلسة *مستقرة* لا على "اليوم".

factory.py         التجميع: DataLayer + إعدادات البيئة.

VERIFYING THE OFFICIAL SCRAPER ON YOUR NETWORK
──────────────────────────────────────────────
شبكة بيئة التطوير هنا مغلقة أمام egx.com.eg (استُوثق ذلك: TLS/SSL connection
closed لكل endpoint)، لذلك:

  ✓ ما هو مُثبَت باختبارات: قراءة الجداول، ترويسات ذات مستويين مع rowspan،
    الأرقام العربية، مطابقة الأعمدة، سلسلة المرشحات، تعلّم الـendpoint،
    تحويل JSON المضمّن، تقارير الفشل، بوابات الجودة، الراوتر، المخزن،
    والابتلاع — كلها على fixtures حقيقية الشكل (tests/fixtures/egx/).

  ⚠ ما يحتاج تشغيل مرة واحدة عندك: `probe`. يطبع لكل endpoint الحالة، عدد
    البايتات، عدد الجداول، عدد الصفوف المقروءة، والحقول الناقصة. لو ظهر
    تغيير فى تصميم الموقع، الـprobe يكشفه فورًا، والمطلوب عادةً إضافة
    مرادف عمود أو مسار endpoint فى ملف واحد (egx_official.py).

هذه الطبقة (البيانات) شرط مسبق لا بديل: لا يمكن معايرة أى مؤشر على بيانات
لا تعرف مصدرها ولا عمرها. بعد إتمامها، بناء الكشف يسير على ثلاث مراحل:

PHASE A — إعادة صياغة الإشارة كفرضية قابلة للاختبار
  كل شرط فى egx_smart_money_core.py (buy/sell ratio > 1.5، POC تحت السعر،
  OBV أعلى من متوسطه…) يصبح فرضية H قابلة للقياس على تاريخ فعلى:
      H: "عندما يتحقق الشرط X على (رمز، جلسة)، فإن العائد بعد 5/10/20 جلسة
          يختلف عن العائد الأساسى (base rate) بفرق ذى دلالة إحصائية."
  لا يُقبل الشرط لأنه "منطقى"، بل لأنه اجتاز اختبارًا.

PHASE B — القياس مع أخذ تعدّد الاختبارات فى الحساب
  لكل شرط: عدد الحالات، معدل النجاح، الفرق عن الأساس، فترة ثقة،
  وp-value مصحّحة (Benjamini–Hochberg) لأن تجربة عشرات الشروط على نفس
  البيانات تُنتج "دلالة" وهمية بسهولة. + التجنب الإلزامى لـ look-ahead
  (الإشارة تُحسب على إغلاق الجلسة t، والعائد من t+1).

PHASE C — التحقق الزمنى (Walk-forward)
  التقسيم: تدريب على فترة، اختبار على ما بعدها، بلا رجوع للخلف. يُقبل
  الشرط فقط إذا استمر أداؤه خارج عينة التدريب، ويُخزَّن معدل نجاحه
  المُقاس داخل الـstore ليُقرأ مع كل إشارة.

النتيجة المستهدفة: كل إشارة تخرج ومعها صف واحد صريح:
    { الشرط، عدد الحالات تاريخيًا، معدل النجاح المُقاس، الأساس،
      الفرق، فترة الثقة، حالة التحقق خارج العينة }
أى أن الرقم لم يعد "رأيًا" بل "قياسًا مُوثَّقًا" — وهذا هو الفارق بين
احتمال مُعايَر واحتمال مُدّعى.
