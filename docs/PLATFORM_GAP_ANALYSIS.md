# تحليل الفجوات: البرومبنت الرئيسي (QuantFlow AI) مقابل المستودع الحالي

**التاريخ:** 2026-10-11
**الفرع:** `arena/d03f4a9c-egx-mcp`
**الغرض:** مقارنة متطلبات البرومبنت بما هو منفذ فعلًا، وتحديد ما يتعارض مع النطاق المتفق عليه، وما يحتاج قرارًا قبل البناء.

الحالات: **موجود** = منفذ ومُختبر · **جزئي** = منفذ بجزء من المتطلب · **ناقص** = غير منفذ · **متعارض** = يخالف قاعدة متفق عليها · **معلّق** = لا يوجد مصدر حر موثّق.

## 1. الهيكل المعماري

البرومبنت يطلب FastAPI + React + PostgreSQL + Docker. المستودع الحالي هو **خادم MCP** (FastMCP) يعمل داخل OpenCode، ويخزن البيانات في SQLite (`egx_data.db`). لا توجد واجهة React ولا FastAPI ولا PostgreSQL.

**القرار المطلوب (سؤال 1 أدناه):** هل تُبنى المنصة كطبقة جديدة فوق المحرك، أم تُوسَّع أدوات MCP فقط؟

## 3. مصادر البيانات

| المتطلب | الحالة | ملاحظة |
|---|---|---|
| OHLCV يومي (EGX Official + Yahoo) | موجود | طبقة بيانات بمصدر وجودة وتوقيت لكل قيمة |
| أسعار داخل اليوم (5/15/60 دقيقة) | ناقص | لم يُتحقق من مصدر حر موثوق؛ الوصول إلى EGX وYahoo محجوب من بيئة التطوير |
| البيانات الأساسية (قوائم مالية، أسهم حرة، توزيعات) | معلّق | لا يوجد مصدر حر موثّق بعد |

| تدفقات الصناديق الفعلية | معلّق | لا مصدر حر موثّق |
| Bid/Ask وعمق الدفتر والصفقات الفردية | معلّق | مؤجل بقرار سابق |
| الأخبار | ناقص | لم يُختر مصدر حر موثّق |
| إدارة مفاتيح API | جزئي | `.env.example` موجود؛ لا توجد مفاتيح مطلوبة حاليًا |

## 4. كشف التجميع والتصريف

| الطريقة في البرومبنت | الحالة | الموجود |
|---|---|---|
| 1. حركة السعر والحجم | جزئي | `egx_accumulation_fingerprint` (شذوذ الحجم، مناطق التجميع، الامتصاص، تحضير الاختراق)، ومعايرتها عبر `egx_event_study` |
| 2. تحليل نطاق التداول | جزئي | مناطق التجميع في البصمة؛ لا يوجد كشف آلي للنطاقات بطرق قابلة للاختبار بعد |
| 3. الحجم التراكمي (OBV, A/D, CMF, MFI, VPT, RVOL) | جزئي | OBV وADL مُعايَران في محرك الأحداث؛ CMF وMFI وVPT وRVOL وVolume Oscillator غير منفذة (تحقق بالبحث في الكود) |
| 4. VWAP وVolume Profile | جزئي | Volume Profile/POC موجودان في محرك الأحداث؛ VWAP موجود بصيغة تقريبية على نافذة داخل `egx_smart_money_core` غير مُعايَر؛ VWAP اليومي والمرتكز (Anchored) غير منفذ |
| 5. ضغط الشراء والبيع (Delta) | معلّق | يتطلب بيانات تنفيذ؛ غير متاحة من مصدر حر |
| 6. الامتصاص والاختراق الكاذب | جزئي | الامتصاص في البصمة؛ Spring وSelling Climax وNo-Supply وSecondary Test في Wyckoff؛ الاختراق الكاذب غير منفذ |
| 7. تحليل متعدد الأطر الزمنية | ناقص | التخزين يومي فقط؛ لا محاذاة للأطر الأخرى |
| 8. المقارنة النسبية (مؤشر/قطاع/أقران) | جزئي | تدوير القطاعات مُعايَر؛ القوة النسبية للسهم مقابل المؤشر غير مُقاسة بعد |
| 9. الحالات غير الطبيعية (Robust Z, Change Point) | ناقص | لا يوجد |
| 10. ربط الأحداث والإفصاحات | ناقص | يعتمد على مصادر الإفصاح (غير مكتملة) |

**ملاحظة:** البرومبنت يطلب "محرك تقييم موحد" لا يكون متوسطًا لمؤشرات مترابطة. هذا غير منفذ. الموجود حاليًا هو أحكام لكل شرط على حدة (VALIDATED / SUGGESTIVE / REJECTED / NO_EVENTS).

## 5. محرك التقييم وتدفقات الأموال والسيولة

- **درجة الأدلة المتوافقة مع التجميع والتصريف (مع أسباب وأدلة معارضة وشروط إبطال):** ناقص.
- **تدفقات الأموال:** جزئي — الحجم بالقيمة النقدية وتقدير التدفق من الشموع فقط. تدفقات الأوامر والمؤسسية معلّقة.
- **السيولة:** جزئي — متوسط القيمة اليومية من البيانات المخزنة. السبريد والعمق وتأثير الحجم معلّقة.

## 6. المسح (Screener)

- `egx_stock_screener` موجود. **لم أفحص بعد** ما إذا كانت شروطه معايَرة أم قواعد ثابتة؛ هذا فحص لازم قبل الادعاء بأنه يطابق البرومبنت.
- القوائم المحفوظة، والتنبيهات، وإعادة تشغيل الفلاتر: ناقصة.

## 7. التحليل الأساسي والتقييم (DCF)

ناقص بالكامل. ولا يمكن البدء قبل وجود مصدر حر موثّق للقوائم المالية للشركات المدرجة في البورصة المصرية.

## 8. الذكاء الاصطناعي

- النموذج الذي يستدعي الأدوات (داخل OpenCode) هو الذي يشرح النتائج. لا حاجة لطبقة LLM داخلية منفصلة في خادم MCP.
- الموجود: قاموس `glossary` في كل استجابة إحصائية يشرح الأحكام والأرقام.
- ناقص: أدوات الحماية من حقن التعليمات في الأخبار والمستندات (لا توجد أخبار بعد)، وسجل تحقق من الأرقام في الإجابات.

## 9. إدارة المخاطر

| المتطلب | الحالة |
|---|---|
| التقلب التاريخي، ATR، أقصى تراجع | ناقص داخل محرك EGX |
| حجم المركز وفق قواعد المستخدم | **متعارض** مع النطاق المتفق عليه (لا حجم مركز) |
| مستويات إبطال الفرضية | ناقص (يمكن إضافتها كشروط قابلة للقياس وليست أوامر) |
| ارتباط المراكز، سيناريوهات الضغط | ناقص |

## 10. الاختبار التاريخي

- محرك الأحداث مع تبديل الكتل وwalk-forward موجود ومُختبر.
- محاكاة المحفظة الكاملة مع التكاليف والانزلاق وتجنب تسرب البيانات المستقبلية: **ناقصة**.
- أدوات `backtest_strategy` و`walk_forward_backtest_strategy` الموجودة تقرأ من Yahoo Finance عبر خدمة قديمة في المستودع، وليست مربوطة بطبقة بيانات EGX المخزنة، ولم تُفحص لتكاليف EGX أو لتجنب التسرب المستقبلي. لا تُعدّ دليلًا على جودة استراتيجيات EGX.
- مكتبات الاختبار التاريخي المعروفة (`backtesting`, `backtrader`) مرفوضة بسبب الترخيص (AGPL/GPL). `vectorbt` و`arch` ترخيصهما غير موثّق.

## 11. اختبار كشف التجميع على بيانات اصطناعية

- موجود: ضوابط للتجميع المزروع والضجيج والمحاكاة لـ Wyckoff وتدوير القطاعات، بقيم أساس وFPR موثّقة.
- ناقص: حالات البرومبنت الإضافية (انخفاض بحجم مرتفع، سهم منخفض السيولة، سهم شديد التقلب، أسواق جانبية وهابطة، بيانات ناقصة ومكررة، تجزئة أسهم، حجم مرتفع قرب الأرباح، إشارات متعارضة بين الأطر الزمنية) مع حقيقة مرجعية لكل حالة وقياس Precision وRecall وF1.

## 16. تعارضات مع قواعد متفق عليها (تحتاج قرارًا)

1. **`egx_trade_plan`** (موجودة في المستودع وطلبتها في القائمة): تُرجع حقل `recommendation` وأهدافًا ووقف خسارة ونسبة مخاطرة/عائد. هذه مخرجات **غير معايَرة** وتخالف قاعدة "لا أوامر شراء/بيع". يحتاج قرارًا (سؤال 2).
2. **`egx_accumulation_detector.py`**: ملف غير مستورد من أي مكان، ويعتمد على `yfinance` وهي غير مدرجة في المتطلبات، ويُرجع `next_target` و`institutional_signals`. أقترح حذفه لأنه ميت ويخالف القواعد، بعد موافقتك.
3. **حجم المركز وقواعد 2/5/10%**: مخالفة للنطاق المتفق عليه.
4. **الربط بحساب الوساطة والتداول**: مستبعد بالكامل.
5. **مصادر مدفوعة أو مرخّصة** (مثل BrokerFlowProvider): مستبعدة.
